# `dubna-site-demos` — публичное демо

**Репозиторий:** https://github.com/mirzemkv/dubna-site-demos  
**Витрина:** https://mirzemkv.github.io/dubna-site-demos/  
**Демо для караоке:** https://mirzemkv.github.io/dubna-site-demos/los-los/

Это отдельный **публичный** репозиторий для GitHub Pages. Здесь только демо-макеты, без личных файлов, памяти, клиентских баз и паролей.

---

## Что внутри

```
public-demo/
  index.html          — страница со списком демо
  los-los/
    index.html        — демо для караоке-гастропаба
    los-los-logo.jpg  — логотип
  .nojekyll           — чтобы GitHub Pages не трогал файлы
```

---

## Как обновить

Из папки `D:\work\public-demo`:

```powershell
git add .
git commit -m "Демо: что изменил"
git push
```

GitHub Pages пересоберёт страницу за 1–2 минуты.

Проверить статус сборки:

```powershell
gh api repos/mirzemkv/dubna-site-demos/pages
```

### Свой домен (опционально)

Если нужен красивый адрес для демо — купите отдельный домен, например `demo-loslosos.ru`, и добавьте CNAME на `mirzemkv.github.io`. Для клиентского продакшна всё равно нужен российский VPS, GitHub Pages — только витрина.

## Правила публикации

1. **Никогда** не публиковать из приватного проекта с памятью.
2. В репозитории не должно быть: телефонов клиентов, паролей, SSH-ключей, баз, скриншотов переписок, личных файлов.
3. Демо с брендом заведения публикуется **только как явно помеченный демо-макет**. На каждой странице — бейдж «Демо-макет · не официальный сайт».
4. Не выдавать демо за официальный сайт заведения.
5. Если владелец против — удалить демо из публичного репозитория в тот же день.
6. Перед публикацией нового заведения проверять: нет телефонов клиентов, паролей, ключей, баз и личных файлов.
